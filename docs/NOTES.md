# Portfolio refactor notes

Branch: `nextjs-refactor`. The original static site (Jarvis HUD, plain HTML/CSS/JS, GitHub Pages) is still on `main`. To see old code: `git show main:script.js`.

## Decisions (agreed with owner)
- Fresh design, content reused only. Not a 1:1 port.
- Deploy target: Vercel. The `CNAME` file is a leftover from GitHub Pages; remove it and add `huyhg.dev` in Vercel settings and DNS.
- three.js via React Three Fiber + drei. New branch in the same repo.
- Concept: Tony Stark / Tom Holland. First-person holo desk, Jarvis HUD only on the overview screen. Theme toggle: J.A.R.V.I.S. (red/gold/cyan) and K.A.R.E.N. (Spidey red/blue).

## Stack
Next.js 16 (Turbopack, cacheComponents on), React 19.3, Tailwind v4, three 0.186, @react-three/fiber 9, drei 10, @react-three/postprocessing (Bloom).
`AGENTS.md` (generated by create-next-app) warns Next 16 has breaking changes. Read `node_modules/next/dist/docs/` before touching framework APIs.

## Layout
- `src/data/portfolio.ts`: all content, typed. Also `stats` for the HUD. Edit here, not in components.
- `src/data/themes.ts`: palettes. Single source of truth: applied as CSS vars on the root wrapper (`Portfolio.tsx`) and read directly by three.js.
- `src/data/sections.ts`: section ids, label, GLB model path, and the Jarvis/Karen AI lines.
- `src/components/Portfolio.tsx`: client root. State: theme, active section, boot, AI line. Holds the panel and nav.
- `Scene.tsx` (desk, pads, beams, camera rig, bloom), `Hologram.tsx` (shader + wireframe edges + size normalisation), `SceneLoader.tsx` (`ssr:false` dynamic import).
- `Hud.tsx` (top bar, overview cards, AI line), `Boot.tsx`, `Typed.tsx`, `Sections.tsx` (server-safe section bodies, reused in sr-only SEO copy in `page.tsx`).
- `src/app/globals.css`: tokens, `.hud-card` (overview HUD), `.holo-panel` (hologram panel).
- `public/models/*.glb` (CC0, credits in `LICENSES.md`), `public/fonts/Orbitron.ttf` (labels in 3D).

## Research findings
- Stark workshop look: dark room, glass/metal table, translucent holograms projected above it, no solid UI cards. The film's holograms are expanded wireframe projections.
- Hologram shader recipe (hologram-shader write-ups): fresnel rim + moving scanlines + sweep band + flicker; `AdditiveBlending`, `DoubleSide`, `depthWrite:false`, `transparent:true`. Glow comes from Bloom, not the material.
- Wireframe edge layer (`EdgesGeometry`, 25 deg threshold) is what makes it read as wireframe. A solid additive fill alone saturates to a blue blob.
- poly.pizza pages are JS-rendered, but the raw HTML contains `https://static.poly.pizza/<uuid>.glb`; grep it with curl.
- Models used: Kenney laptop and satellite dish, cg_world crane, Polygonal Mind robot, Quaternius spaceship. All CC0.

## Gotchas hit (don't repeat)
- Unlayered CSS beats Tailwind layers. `.hud-card { position: relative }` overrode `absolute` and misplaced the card. Don't set `position` in custom classes that are also given position utilities.
- `filter` (or an animated `filter`) on an element makes it a backdrop root, which silently disables its own `backdrop-filter`. Keyframes for `.holo-panel` must not use `filter`.
- React Compiler lint rules: no mutating memoized values inside `useFrame` (pass via refs set in an effect), no array of `useRef` calls, no `setState` directly in effects, no `//` text in JSX.
- drei `Html` labels produced a React "unmount a root while rendering" error and draw over everything. Replaced with drei `Text` (local font).
- The CC0 CPU and circuit-board models are flat plates: they rotate into thin slivers. Prefer chunky models.
- Dev server can serve stale CSS or JS after edits (watcher missed changes) or die when a shell call ends. Fix: `pkill -f "next dev"; rm -rf .next; nohup npm run dev > /tmp/pf/dev.log 2>&1 &`.
- Headless window resize clamps width to about 500px. Use `emulate` with viewport `390x800x2,mobile,touch` for real mobile checks.
- `take_screenshot` without `filePath` reuses one temp file and can return a stale image. Use an explicit `filePath` inside the project (`.shots/` is gitignored).

## Verified
tsc and eslint clean, `npm run build` OK (fully static). Headless Chrome: boot, overview, open/close section via nav and Esc, theme toggle, no console errors. Mobile measured at real 390x800: no overlaps, no horizontal scroll. Not tested in Vivaldi.

## Known issues / next steps
1. Crane reads as a thin line and its top goes behind the profile card. Swap model or rescale; normalisation uses the longest side.
2. Section panel is a DOM element with CSS 3D tilt, not a WebGL object, so the desk cannot occlude it. Option: `Html transform` or WebGL plane with the text as texture. Watch the root-unmount issue.
3. No desk clutter props (mug, tools, keyboard). Add a few real CC0 props for the lived-in workshop feel.
4. K.A.R.E.N. theme not re-checked on the new scene.
5. Low-end GPU/perf untested (Bloom, 2 MB `crane.glb`). Consider draco/meshopt compression and a quality toggle.
6. Mobile top bar title wraps to two lines.
7. Keyboard focus does not move into the panel on open. Add focus management; flicker and sweep already disabled under `prefers-reduced-motion`.
8. Labels use Orbitron TTF through troika; a variable font works at default weight only.
9. Remove `CNAME` when moving to Vercel; update metadata and add an OG image.
10. Overview HUD cards still use the old HUD style by design. Revisit if the whole UI should go holographic.
11. Spidey ideas: web-lattice grid, suit-red/blue pads, a mask hologram.
